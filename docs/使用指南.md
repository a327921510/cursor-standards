# cursor-std 使用指南

`cursor-std` 是一套语言无关的 Cursor Rules / Skills 分发工具。分发机制为
**copy + `.standards-lock.json` + clean sync + 完整性 manifest**。

- **copy**：把规范文件复制到目标项目的 `.cursor/` 下（不依赖 symlink，Windows/Git Bash 友好）。
- **clean sync**：每次同步时**原子替换**受管子目录 `.cursor/rules/standards` 与 `.cursor/skills/standards`——先清空再落地，因此中央仓库删除的文件会被传播，同时**绝不触碰**同级的 `local.mdc` 等本地文件。
- **`.standards-lock.json`**：记录来源、版本、commit、安装模式、CLI 版本、是否 dirty，以及完整性 manifest。
- **manifest**：受管文件的 sha256 清单，`verify` 用它检测手改 / 缺失 / 多余文件。

## 1. 安装 CLI

按操作系统选用不同的安装脚本：

| 系统 | 脚本 | 说明 |
|------|------|------|
| macOS / Linux | `./install.sh` | 软链接到 `~/.local/bin` |
| Windows（Git Bash） | `./install-windows.sh` | 写入 wrapper（MSYS 下 `ln -s` 不可靠） |

可用 `BIN_DIR=/usr/local/bin ./install.sh`（或 Windows 脚本）自定义安装位置。

### macOS / Linux

```bash
git clone <cursor-standards repo> ~/dev/cursor-standards
cd ~/dev/cursor-standards
./install.sh
export STANDARDS_HOME=~/dev/cursor-standards   # 建议写入 ~/.bashrc / ~/.zshrc
```

### Windows（Git Bash）

本工具是 Bash 脚本，**不要**在 PowerShell / CMD 里跑安装脚本。请用 [Git for Windows](https://git-scm.com/download/win) 自带的 **Git Bash**（不要用 `C:\Windows\System32\bash.exe`，那是 WSL 入口，未装发行版时会报错）。

```bash
# 在 Git Bash 中（路径用 /d/... 形式，不要用 D:\...）
git clone <cursor-standards repo> /d/dev/cursor-standards
cd /d/dev/cursor-standards
./install-windows.sh
export PATH="$HOME/.local/bin:$PATH"
export STANDARDS_HOME=/d/dev/cursor-standards   # 建议写入 ~/.bashrc
cursor-std version
```

说明：

- Git Bash / MSYS 上 `ln -s` 常常变成文件拷贝，导致 CLI 找不到 `lib/`；因此 Windows 专用 `install-windows.sh`，始终写 wrapper。
- Windows 路径在 Git Bash 中写成 `/d/project/...`，对应 `D:\project\...`。
- 日常命令（`install` / `check` / `update`）用 **copy** 模式下发规范，不依赖 symlink。

## 2. 命令总览

| 命令 | 作用 | 关键退出码 |
|------|------|-----------|
| `cursor-std install [目标]` | 同步 rules/skills 到 `<目标>/.cursor/` 并写 lock + manifest | 0 成功 |
| `cursor-std check [目标]` | 对比 lock 版本与最新版本 | **0** 最新 / **1** 有升级 / **3** 无法判定 |
| `cursor-std update [目标]` | fetch 最新并重新 install | 0 成功 |
| `cursor-std verify [目标]` | 用 manifest 校验受管文件完整性 | **0** 一致 / **4** 检测到 drift |
| `cursor-std remove [目标]` | 卸载：删除受管子目录 + lock（保留 `local.mdc`、`req-workflow.local.mdc` 与 hooks） | 0 成功 |
| `cursor-std init [目标]` | install + 写入升级提醒 hook（不覆盖已有 hooks.json） | 0 成功 |
| `cursor-std configure-req [目标]` | 写入 REQ 工作流本地路径配置（不受 clean sync 覆盖） | 0 成功 |
| `cursor-std version` | 打印 CLI 与 standards 版本 | 0 |
| `cursor-std help` | 帮助 | 0 |

> 目标目录省略时默认为当前目录 `.`。

## 3. 选项

| 选项 | 说明 |
|------|------|
| `--source <dir>` | 指定 standards 源 checkout（覆盖 `$STANDARDS_HOME` 与内置 self） |
| `--version <tag>` | pin 到某个 git tag/版本（经 `git archive`，不改动源工作树） |
| `--commit <sha>` | pin 到某个 commit |
| `--global` | 安装到 `$HOME/.cursor`（用户级，所有项目共享） |
| `--mode <copy>` | 安装模式（当前仅支持 `copy`） |
| `--doc-root <dir>` | `configure-req`：文档根绝对路径 |
| `--repo <label>=<dir>` | `configure-req`：代码仓（可重复，至少 1 个） |
| `--feature-doc <rel>` | `configure-req`：功能真相相对路径（默认 `项目功能需求文档.md`） |
| `--changelog <rel>` | `configure-req`：changelog 相对路径（默认 `changelog.md`） |
| `--seed-docs` | `configure-req`：向文档根复制 backlog/changelog stub（已存在则跳过） |
| `--force` | `configure-req`：覆盖已有 `req-workflow.local.mdc` |

## 4. 环境变量

| 变量 | 用途 |
|------|------|
| `STANDARDS_HOME` | 本地 cursor-standards clone 路径；设置后可**离线**安装 |
| `STANDARDS_REPO` | `check` 在缺少 lock/source 时使用的远程 URL |
| `STANDARDS_CHECK_TTL` | hook 缓存 check 结果的秒数（默认 21600 = 6h） |

## 5. 典型工作流

### 5.1 首次接入一个项目

```bash
cursor-std init /path/to/my-app      # install + 写升级提醒 hook
# 或仅安装规范（不写 hook）：
cursor-std install /path/to/my-app
```

安装后的目标结构：

```
my-app/.cursor/
├── rules/
│   ├── standards/        # 来自中央仓库，勿手改
│   │   ├── std-general.mdc
│   │   ├── std-git-workflow.mdc
│   │   ├── std-req-workflow.mdc   # REQ 工作流摘要
│   │   ├── std-python.mdc
│   │   └── std-typescript.mdc
│   ├── local.mdc                  # 项目本地规则（手动；cursor-std 不会动）
│   └── req-workflow.local.mdc     # configure-req 生成；upgrade 不覆盖
├── skills/standards/     # commit-helper / pr-workflow / req-* / implement-req / add-e2e-test / sync-req-docs
├── hooks.json            # init 写入（若已存在则保留原文件）
├── hooks/check-standards.sh
└── .standards-lock.json  # 版本锁 + manifest
```

### 5.2 接入 REQ 文档驱动工作流

`install` / `init` 只会下发通用规则与 skill，**不会**猜测你的文档仓与代码仓。第二步由你提供路径：

```bash
# 在「接入 standards 的那个项目根」上配置（也可对 workspace 中任一仓执行）
cursor-std configure-req /path/to/my-app \
  --doc-root /path/to/docs \
  --repo app=/path/to/app \
  --repo boss=/path/to/boss \
  --seed-docs
```

多仓示例（文档与代码分离）：

```bash
cursor-std install /path/to/upower_app
cursor-std configure-req /path/to/upower_app \
  --doc-root /path/to/upower_doc \
  --repo app=/path/to/upower_app \
  --repo boss=/path/to/upower_boss \
  --seed-docs   # 仅当文档仓尚无 backlog 时有用；已有台账会跳过覆盖
```

说明：

- 写出 `.cursor/rules/req-workflow.local.mdc`（`alwaysApply`），Agent 以此定位文档根与代码仓。
- `install` / `update` / `remove` **不删除、不覆盖**该文件（`remove` 只清 `standards/` 与 lock）。
- 已存在时需 `--force` 才能覆盖。
- 缺参且 stdin 为 TTY 时可交互填写；CI / 脚本请始终传 flags。
- Cursor 口令：`按工作流登记需求` → `按 REQ-xxx 实现` →（可选）`REQ-xxx 主路径已定，补 E2E` → `REQ-xxx 已确认，同步文档`。细则见已安装的 `req-workflow` skill（`WORKFLOW.md`）。

### 5.2.1 前端 E2E 与小程序占位（可选）

与流程地图 **stage** 对齐：主路径定稿后再补页面 E2E（skill：`add-e2e-test`）。约定要点：

- 定位属性默认 `data-testid="{feature}.{stage}"`（项目可在 `local.mdc` 覆盖）。
- 只给本 REQ 用例会点到的控件打标；优先 role / 可见名称。
- 小程序自动化：中央规范仅要求 `e2e/miniprogram/README.md` **占位**（与 H5 共用 stage 名），不生成驱动代码。
- 人工步骤级测试用例仍用归档后的「生成详细测试用例」，与 E2E 不是一回事。

pin 测试版 standards 示例：

```bash
cursor-std install /path/to/my-app --version 0.2.0-test.3
```

### 5.3 日常检查与升级

```bash
cursor-std check  /path/to/my-app     # 退出码 1 表示有新版本
cursor-std update /path/to/my-app     # 升级到最新
```

### 5.4 锁定版本（生产分支 / 强合规）

```bash
cursor-std install /path/to/my-app --version 1.2.0
cursor-std install /path/to/my-app --commit  abc123
```

### 5.5 全局基线（一次装、跨项目生效）

```bash
cursor-std install --global           # 装到 ~/.cursor/，Cursor 对所有项目生效
```

> 全局基线适合「通用软规范」；需要按项目锁版本时，用项目级 `install` + lock。  
> REQ 路径配置建议放在**项目级** `configure-req`，不要依赖全局猜路径。

### 5.6 CI 中做版本闸门

```yaml
# .github/workflows/cursor-standards.yml
- name: Check cursor standards version
  run: |
    cursor-std check .            # 落后则退出码 1，使 job 失败
    # 或 warn-only：cursor-std check . || echo "::warning::standards outdated"
```

### 5.7 校验是否被手改

```bash
cursor-std verify /path/to/my-app     # 退出码 4 表示 standards/ 被手改或损坏
```

### 5.8 卸载

```bash
cursor-std remove /path/to/my-app     # 删除 standards/ 子目录与 lock
```

只移除受管内容（`.cursor/rules/standards`、`.cursor/skills/standards`、`.standards-lock.json`），
**保留** `local.mdc`、`req-workflow.local.mdc`、`hooks.json`、`hooks/`。升级提醒 hook 如需一并移除请手动删除。

> 下发规则统一带 `std-` 前缀（如 `std-general.mdc`），避免与项目本地规则重名、`@` 引用歧义。

## 6. 升级提醒 hook 如何工作

`init` 会写入 `.cursor/hooks/check-standards.sh` 并（在不存在时）写入 `.cursor/hooks.json`，
在 Cursor `sessionStart` 时运行。由于 `sessionStart` 的上下文注入并非 100% 可靠、且**云端 Agent 不触发**该 hook，脚本采用**三层降级**：

1. 返回 `{"additional_context": "..."}` 注入到会话（最佳体验）。
2. 打印到 stderr（终端 / hook 输出可见）。
3. 写入 `.cursor/.standards-check` marker 文件（持久兜底）。

并做了缓存（默认 6h）与「仅在有升级时提示」的降噪。云端场景请用 §5.6 的 CI 闸门兜底。

> 需在 Cursor 设置中启用 Hooks（beta）。hooks.json 中已有配置时，`init` 不会覆盖，而是写出 `.cursor/hooks.standards.json` 供你手动合并。

## 7. 与其他 Cursor 机制的关系

- **User Rules**：放个人偏好；standards 放团队规范，互补。
- **项目本地 Rules**：`.cursor/rules/local.mdc`（可叠加，cursor-std 不管理）。
- **REQ 路径配置**：`.cursor/rules/req-workflow.local.mdc`（`configure-req` 生成，不管理进 standards/）。
- **多来源冲突**：Cursor 会把各来源规则一并提供给 Agent，**没有硬性覆盖优先级**；冲突应靠作用域（globs）与措辞规避，而不是依赖优先级自动消解。

## 8. 兼容性与限制

- 依赖：`bash`、`git`、`coreutils`（`sha256sum` 或 `shasum`）。无需 Node/Python。
- 支持平台：macOS、Linux、Windows（**Git Bash** / MSYS）。原生 PowerShell 不支持。
- 语言无关的 semver 比较为纯 bash 实现，不依赖 GNU `sort -V`。
- 当前仅支持 `copy` 模式；`symlink` 模式在路线图中（见待确认问题）。
- `.mdc` 规则中带 `globs` 的规则在 Cursor 2.0+ 为「文件进入上下文（@ 引用/被编辑）时」附加，并非「打开项目即常驻」；常驻规范请用 `alwaysApply: true`（如 `general.mdc`）。
